LOT 1 – Infrastructure réseau

Objectif Mettre en place une infrastructure réseau sécurisée, segmentée et performante sur un Switch Core (L3) et 2 switches d’accès (L2) : VLAN, routage inter‑VLAN, NAT (via Stormshield) et plan d’adressage.

À livrer (Lot 1)
  • Schéma logique & physique (Core ⇄ Access ⇄ Stormshield).
  • Plan d’adressage VLAN + IP SVI.
  • Configs sauvegardées : Core & Access, règles de base sur Stormshield.
  • Journal des tests : ping inter‑VLAN, NAT/Internet, ACL.

Pare‑feu Stormshield

Checklist – Routage, NAT, filtrage
  1. Interfaces/zonage : créer les interfaces pour chaque VLAN (ou transit depuis Core) et affecter les zones (LAN, DMZ, GUEST, WAN).
  2. Routes : route par défaut → WAN, routes statiques si besoin.
  3. NAT sortant : SNAT pour VLAN 20/30/300/DMZ → WAN.
  4. Filtrage : autoriser Clients→Internet (80/443, DNS), Clients→Serveurs (SMB, LDAP), bloquer inverse.
  5. Journalisation et alertes ( Monitoring) : activer logs pour règles critiques.
  6. VPN (option) : portail SSL/IPsec pour accès distant.

Proxmox VE – Bridges & VLAN

Créer les bridges (vmbr) correspondants et taguer les interfaces des VM.

Étapes – Réseau Proxmox
  1. vmbr0 (Mgmt) : IP d’admin en VLAN 10 (Mana) → accès Web/SSH Proxmox.
  2. vmbrX (Serveurs) : trunk vers Core/Stormshield, VLAN tag sur chaque VM.
  3. Tester la connectivité : ping SVI, accès DNS/DHCP (quand dispo).
Extrait /etc/network/interfaces (exemple Debian) 
auto lo
iface lo inet loopback

auto vmbr0
iface vmbr0 inet static
  address 172.16.31.10/19
  gateway 172.16.31.254
  bridge-ports eno1
  bridge-stp off
  bridge-fd 0

# Trunk pour VM (tag VLAN au niveau de la VM)
auto vmbr1
iface vmbr1 inet manual
  bridge-ports eno2
  bridge-stp off
  bridge-fd 0

AD DS 2025 + DNS + DHCP

Procédure – Promote to DC (AD DS)
  1. Installer Windows Server 2025, configurer IP fixe (VLAN Serveurs).
  2. Ajouter rôles : AD DS + DNS + DHCP.
  3. Promouvoir en contrôleur de domaine (nouvelle forêt).
  4. Créer OU, groupes (ex : IT, Users, Startups) et comptes.
DHCP – Portées & options
  • Créer des scopes pour VLAN 20/30/300 : plage, passerelle (SVI), DNS = IP du DC.
  • Réservations pour hôtes critiques (Mac⇄IP).
  • Activer DHCP relay sur Core si serveur DHCP n’est pas dans le même VLAN.
DNS – Zones & enregistrements
  • Zone directe (A) + zone inversée (PTR).
  • Enregistrements pour SRV‑FILES, PROXMOX, GLPI, etc.
  • Transfert conditionnel vers DNS externes si besoin.
PowerShell – Exemples utiles 
# Installer rôles
Install-WindowsFeature AD-Domain-Services,DNS -IncludeManagementTools

# Promouvoir rapidement (exemple simplifié)
Install-ADDSForest -DomainName "stationf.local" -SafeModeAdministratorPassword (Read-Host -AsSecureString)

# Créer OU & groupe\ nNew-ADOrganizationalUnit -Name "Startups" -Path "DC=stationf,DC=local"
New-ADGroup -Name "DevTeam" -GroupScope Global -Path "OU=Startups,DC=stationf,DC=local"

GPO – Sécurité & configuration postes

Exemples de GPO
  • Mot de passe fort (longueur mini, expiration, historique).
  • Désactivation de LM/NTLMv1, durcissement SMB.
  • Déploiement d’imprimantes / partages via préférences.
  • Firewall Windows : règles entrantes/sortantes par profil.
  • Scripts d’ouverture de session (map réseau).

File Server – SMB / NTFS

Étapes
  1. Installer le rôle File and Storage Services.
  2. Créer les partages SMB (ex : \\SRV-FILES\Projets).
  3. Définir les droits NTFS par groupes AD (Lecture/Écriture).
  4. Publier les chemins via GPO (lecteurs mappés).

Windows 11 – Joindre le domaine

Procédure rapide
  1. Configurer l’IP via DHCP du VLAN 20 (ou fixe avec DNS = DC).
  2. Paramètres → Système → À propos → Renommer ce PC (avancé) → Domaine : stationf.local.
  3. Redémarrer, connexion avec STATIONF\utilisateur.
  4. Vérifier l’application des GPO et l’accès SMB.

GLPI – ITSM

Usage conseillé
  • Créer catégories : Incidents, Demandes, Changements.
  • Gabarits : ouverture de ticket pour VLAN/ACL/Serveur.
  • Inventaire (agent) sur Windows 11 et serveurs.
  • Tableau de bord pour le suivi des lots 1–3.

Wi‑Fi / Azure

Principes
  • SSID interne relié au VLAN 30 (Invités) ou segment dédié.
  • WPA2‑Enterprise (si possible) ou PSK fort ; portail invité si souhaité.
  • Isolement client‑client + filtrage Stormshield vers LAN/DMZ.
  • Option Azure AD / Entra pour identité & MDM (Intune).
